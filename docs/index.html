Overview #

StreamControl is a Qt 6 desktop app for managing the dynamic text and graphics that appear on a live stream — scores, player names, country flags, commentator credits, tournament round labels, etc. You fill in fields in the app; StreamControl writes the values to disk as XML and/or JSON, and (optionally) broadcasts them over WebSocket. Your stream overlay reads the file or listens on the socket and updates itself.

It was originally built for fighting-game tournaments but the layout is fully data-driven, so it works for any stream that needs an operator-driven scoreboard or lower-third.

Features #

  • Custom layouts defined in XML — labels, line edits, spin boxes, checkboxes, comboboxes, radio groups, tabbed sections.
  • Outputs streamcontrol.xml and/or streamcontrol.json to a configurable directory every time you hit Save.
  • WebSocket server (built-in) that pushes the JSON payload to every connected overlay the moment you save, plus a fresh snapshot to each client at connect time.
  • Datasets with autocomplete — reuse player names, sponsors, characters, etc. across sessions.
  • Toolbar with configurable labels and comboboxes for global state.
  • Reset / swap / timestamp buttons for one-click match resets, side switches, and time tracking.
  • CLI hooks — invoke external commands with field values substituted in.
  • Global hotkeys (Windows) for triggering buttons without focusing the app.
  • Tweet widget with media download and URL expansion.
  • Challonge widget for pulling bracket data.
  • Dark mode, configurable font sizes, optional always-on-top.

Requirements #

  • Qt 6 (tested against 6.3 – 6.11) with the modules: core, gui, widgets, xml, network, websockets.
  • A C++17 compiler. On Windows, MSVC 2019/2022; on Linux, gcc/clang; on macOS, the Xcode toolchain.

Building #

Windows (Qt Creator)

  1. Install Qt 6 and Qt Creator with the MSVC kit.
  2. Open StreamControl/StreamControl.pro in Qt Creator.
  3. Configure with an MSVC 64-bit kit and build.

Linux / macOS

cd StreamControl
qmake
make

Running #

  1. Launch StreamControl.
  2. On first run you'll be prompted to configure. Open Configuration and set:
    • Output path — where streamcontrol.xml / streamcontrol.json get written.
    • Layout XML — the file describing the form layout.
    • Output format — XML, JSON, or both.
    • WebSocket — enable and pick a port (default 41236) if you want overlays to receive live pushes instead of polling a file.
  3. Fill in the fields, hit Save, and your overlay updates.

WebSocket protocol #

When WebSocket is enabled, StreamControl listens on the configured port (default 41236) on all interfaces.

  • On connect: the server sends a single text frame containing the current StreamControl JSON snapshot to the new client.
  • On save: the server broadcasts the latest JSON snapshot to every connected client as a text frame.

The payload is identical to what streamcontrol.json would contain on disk — a flat JSON object whose keys are the widget IDs from your layout, plus a timestamp field. Example client:

const ws = new WebSocket("ws://localhost:41236");
ws.onmessage = (e) => {
  const data = JSON.parse(e.data);
  console.log(data.pName1, data.pScore1, "-", data.pScore2, data.pName2);
};

Remote control

A client can escalate its connection with the Control Password from Configuration. An escalated client can set widget values and press buttons. Control is off while the password is empty. Tick Disable to turn it off and keep the password.

The password is saved in plain text in settings.xml (websocketPassword), so protect that file. It never travels over the socket. Authentication is a challenge–response using the same scheme as obs-websocket v5, with a salt that changes every time StreamControl starts or the password changes:

secret = base64(sha256(password + salt))
auth   = base64(sha256(secret + challenge))

Control messages are JSON text frames with an op field. Replies go only to the client that sent the request, so overlays that just listen never see them.

→ {"op":"authRequest"}
← {"op":"authChallenge","salt":"…","challenge":"…"}
→ {"op":"auth","auth":"<base64>"}
← {"op":"authResult","ok":true}

Each challenge works for one attempt only, so send a fresh authRequest before each try. After 5 failed attempts the server closes the socket (code 1008). Changing the password logs out every escalated client.

Once authenticated, send actions in a batch. They run in order. A failing action is reported, and the rest of the batch still runs.

{"op":"batch","id":"any-id","actions":[
  {"action":"set",   "id":"pName1",  "value":"Daigo"},
  {"action":"set",   "id":"pScore1", "value":2},
  {"action":"set",   "id":"finals",  "value":true},
  {"action":"set",   "id":"game",    "value":"sf6"},
  {"action":"set",   "id":"side",    "value":"right"},
  {"action":"press", "id":"swap1"},
  {"action":"save"}
]}
ActionApplies toNotes
setlineEditAny string. Numbers are converted to text.
setspinBoxAn integer or numeric string. Values outside the box's min/max are rejected.
setcheckBoxtrue/false, 1/0 or "1"/"0".
setcomboBoxMatches an item's value, then its text. Editable combos accept any text.
setradioGroupA radio button's value.
pressreset, swap, timestamp, setButton buttonsSame as clicking the button. A button with saveonclick still saves.
save—Same as the toolbar Save button: writes the output files and broadcasts.

A batch does not save on its own. End it with {"action":"save"} when the overlay should update. The reply echoes your id and has one result per action:

{"op":"batchResult","id":"any-id","results":[{"ok":true},{"ok":false,"error":"unknown widget 'x'"}]}

If the batch saves, the snapshot broadcast reaches you before the batchResult. Messages with an op field are control replies, and the rest are snapshots. Errors outside a batch come back as {"op":"error","error":"…"}: invalid JSON, an unknown op, or batch before authenticating.

The socket is plain ws://. The password is protected, but values sent after authenticating are not encrypted, so only expose the port on networks you trust. examples/ws_control/control.html is a small test client. Browsers only allow the hashing it uses (crypto.subtle) on http://localhost or https://, so serve the page from localhost rather than opening it as a file://.

Example overlays #

Located under examples/:

  • Basic/ — Minimal HTML overlays demonstrating field readout.
  • scoreflags/ — Fighting-game scoreboard with player names, scores, country flags, and a center text label. Two versions: a CreateJS canvas renderer and a jQuery + jsTween DOM renderer. Polls streamcontrol.xml every 250 ms.
  • scoreflags_ws/ — Same scoreboard, but connects to the WebSocket server and receives pushes on save. Edit the WS_URL constant if StreamControl is on a different host.
  • ws_control/ — Test client for remote control: authenticate with the control password and send batch JSON.

Layout XML reference #

StreamControl's UI is defined by a layout XML file that you point at via Configuration → Layout XML. The file describes the size of the main window, the form widgets you want, an optional toolbar, optional tabs, and an optional CLI hook section. Each interactive widget has an id that becomes a key in streamcontrol.xml / streamcontrol.json / the WebSocket payload.

Document structure #

<!DOCTYPE StreamControlLayout>
<layout width="390" height="140" [tabbed="1"] [fontSize="12"]>
  <toolBar> ... </toolBar>            <!-- optional -->
  <!-- widgets, or <tab>s if tabbed="1" -->
  <cli> ... </cli>                    <!-- optional -->
</layout>

<layout> attributes

AttributeRequiredNotes
widthyesWindow width in pixels.
heightyesWindow height in pixels.
tabbednoIf "1", the top-level children must be <tab> elements.
fontSizenoBase font size used as the default for child widgets.

Geometry #

Every interactive element accepts:

AttributeRequiredNotes
x, yyesPosition in pixels relative to the containing tab / panel.
width, heightyesSize in pixels.
fontSizenoOverrides the layout's base size. 0 (or omitted) inherits.

Top-level widgets #

<label>

Static text on the form. No id.

<label x="10" y="14" width="46" height="13">Title 1</label>

<line>

Separator. No content, no id.

<line x="10" y="30" width="370" height="2"/>

<lineEdit>

Single-line text input.

AttributeRequiredNotes
idyesOutput key.
dataSetnoCSV file (relative to the layout) used for autocomplete.
dataFieldno1-indexed column to pull from dataSet. Default 1.
masternoAnother widget's id; selecting a value there auto-fills this field from the same row.
noSaveno"1" to keep this field out of the dataset's saved entries.
 
<lineEdit id="pName1" x="10" y="10" width="160" height="20"
          dataSet="players.csv">Player 1</lineEdit>
<lineEdit id="pCountry1" x="180" y="10" width="50" height="20"
          dataSet="players.csv" dataField="2" master="pName1">Country</lineEdit>

<spinBox>

AttributeRequiredNotes
idyesOutput key.
maximumnoUpper bound.
increaseHotkeynoGlobal hotkey string to increment.
decreaseHotkeynoGlobal hotkey string to decrement.
 
<spinBox id="pScore1" x="240" y="10" width="40" height="22" maximum="999"/>

<checkBox>

AttributeRequiredNotes
idyesOutput key ("1" / "0").
toggleHotkeynoHotkey to flip state.
checkHotkeynoHotkey that forces checked.
uncheckHotkeynoHotkey that forces unchecked.

<comboBox>

Drop-down. Children are <comboItem> elements.

AttributeRequiredNotes
idyesOutput key.
editableno"1" allows free-text entry.
dataSet / dataField / masternoSame as <lineEdit>.
nextHotkeynoHotkey to cycle to next item.
previousHotkeynoHotkey to cycle to previous item.

<comboItem> children:

AttributeRequiredNotes
valuenoStored value. Defaults to the text content.
selectedno"true" to make this the default item.
 
<comboBox id="round" x="10" y="10" width="120" height="22">
  <comboItem value="WF">Winners Final</comboItem>
  <comboItem value="LF" selected="true">Losers Final</comboItem>
  <comboItem value="GF">Grand Final</comboItem>
</comboBox>

<radioGroup>

AttributeRequiredNotes
idyesOutput key — set to the selected <radioButton>'s value.
 
<radioGroup id="side">
  <radioButton x="10" y="10" width="60" height="20" value="P1">Player 1</radioButton>
  <radioButton x="80" y="10" width="60" height="20" value="P2">Player 2</radioButton>
</radioGroup>

<button>

Buttons don't write a value to the output; they perform an action. The action depends on type.

AttributeRequiredNotes
typeyesreset, swap, timestamp, or setButton.
idyesInternal identifier.
tooltipnoHover text.
hotkeynoGlobal hotkey to trigger the click.
saveonclickno"1" saves immediately after the click.
  • type="reset" — clears one or more fields. Required: reset="id1,id2,...".
  • type="swap" — swaps values between two field sets. Required: swapSet1="..." and swapSet2="...".
  • type="timestamp" — writes the current time to a paired widget identified by the button's id.
  • type="setButton" — forces a widget to a value. Required: widget="targetId", value="...".
<button type="reset" x="290" y="10" width="40" height="23"
        id="clear1" tooltip="Clear Player 1" reset="pName1,pCountry1">Clear</button>

<button type="swap" x="330" y="40" width="40" height="23"
        id="swap" swapSet1="pName1,pScore1,pCountry1"
        swapSet2="pName2,pScore2,pCountry2">Swap</button>

<tweet>

AttributeRequiredNotes
idyesOutput key prefix.
picPathnoSubfolder for downloaded media. Defaults to twitter.
embedJSONno"1" embeds the raw tweet JSON in the output.

<challonge> and <smashgg>

Bracket-provider widgets that pull match data. Common required attributes: id, playerOneWidget, playerTwoWidget, tournamentStageWidget, bracketWidget, outputType, outputFileName. Optional: playerOneCountryWidget, playerTwoCountryWidget, clearWidgets. Nested stage elements (<grandFinal>, <winnersFinal>, <losersFinal>, …) configure label overrides per bracket stage.

Tabs #

Two ways to use tabs:

1. Whole layout is tabbed. Set tabbed="1" on <layout> and make every child a <tab>:

<layout width="390" height="140" tabbed="1">
  <tab name="Match Info"> ... widgets ... </tab>
  <tab name="Commentary"> ... </tab>
</layout>

2. A tabbed panel inside a non-tabbed layout. Use a <tabSet> with its own geometry:

<tabSet x="10" y="50" width="370" height="80">
  <tab name="Page 1"> ... </tab>
  <tab name="Page 2"> ... </tab>
</tabSet>
AttributeRequiredNotes
nameyesTab label.
scrollableno"1" wraps the tab in a scroll area.

Toolbar #

A horizontal bar across the top, useful for stream-wide state (event name, round selector). Children are laid out left-to-right; no geometry attributes on the children. Allowed children: <label>, <comboBox>, and <button type="setButton" ...>.

<toolBar>
  <label>Event:</label>
  <comboBox id="eventName" editable="1">
    <comboItem>Weekly #1</comboItem>
    <comboItem>Majors</comboItem>
  </comboBox>
</toolBar>

CLI #

Run external commands when you hit Save. Variables from any widget can be interpolated with [$id] or [$id.field].

<cli>
  <cmd>notify-send "Match" "[$pName1] vs [$pName2]"</cmd>
  <cmd ignore="pScore1,pScore2">obs-cli scene "MainCam"</cmd>
</cli>
AttributeRequiredNotes
ignorenoCSV of widget IDs whose changes should not trigger this command.

Output mapping #

When you Save, every widget with an id becomes a key in the output:

WidgetJSON value
lineEditstring
spinBoxstring (the number)
checkBox"1" or "0"
comboBoxselected item's value (or its text)
radioGroupselected <radioButton>'s value
tweettweet text (and JSON if embedJSON="1")
timestamp buttonwrites to a paired field of the same id

A top-level timestamp key is always added (seconds since epoch of the save). Static <label>, <line>, and button widgets do not contribute output.

Tips #

  • Keep dataset CSVs next to the layout file so relative paths work.
  • IDs are also what the WebSocket payload uses — design them so overlay code can consume them directly (pName1, pScore1, etc.).
  • Hotkeys are Windows-only. The string format is whatever Qt's QKeySequence accepts (e.g. "Ctrl+Shift+R").
  • When validating your file, StreamControl will pop up specific error messages — the validators are exhaustive (see MainWindow::checkLayout).
